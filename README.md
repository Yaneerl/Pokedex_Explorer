# PokéDex Explorer

PokéDex Explorer היא אפליקציית Frontend לגילוי פוקימונים, צפייה בפרטים, שמירת מועדפים והשוואת Base Stats. הנתונים נטענים מ-PokéAPI, והממשק מעוצב בהשראת מכשיר Pokédex קלאסי.

הפרויקט בנוי ב-React + Vite + TypeScript עם React Router, CSS מקומי ו-fetch מובנה. אין שרת ייעודי, בסיס נתונים, חשבונות משתמש או ספריית UI.

## עמודים וניווט

| עמוד | נתיב | תוכן |
|---|---|---|
| Pokédex | `/` | קטלוג, חיפוש, סינון, מיון, דפדוף ופוקימון היום |
| Pokémon Details | `/pokemon/:id` | פרטי פוקימון לפי מזהה מספרי, כולל פתיחה ישירה מהכתובת |
| Favorites | `/favorites` | הצגת המועדפים, הסרה ומעבר לפרטים |
| Pokémon Comparison | `/compare` | בחירת שני פוקימונים והשוואת ששת מדדי הבסיס |

נתיב לא מוכר מפנה לקטלוג. הניווט משתמש ב-BrowserRouter; בפריסה לאחסון סטטי יש להגדיר fallback ל-`index.html` כדי שגם פתיחת נתיבים ישירה תעבוד.

## פיצ'רים קיימים

- **קטלוג:** חיפוש לפי שם חלקי או מספר Pokédex מדויק, סינון לפי סוג ודור, סיווג Regular/Legendary/Mythical, מיון לפי שם או מספר, Reset Filters ודפדוף של עד 20 פוקימונים בעמוד.
- **כרטיסי הקטלוג:** תמונות, מספרים, שמות, תגיות עם סמלי SVG מקוריים לכל 18 הסוגים וכפתור מועדפים נפרד מהניווט לפרטים.
- **פרטים:** תמונה גדולה וממורכזת ללא פודיום, אפקט עומק אינטראקטיבי ורקע בתנועה עדינה לפי הסוג. Legendary/Mythical מזוהים משדות המין ב-API ומקבלים תגית וחלקיקי אור; אפקטי התנועה מכבדים prefers-reduced-motion. מוצגים Genus ותיאור אנגלי מתוך נתוני species, עם ניקוי רווחים וכפילויות ו-fallback למידע חסר.
- **נתוני הפוקימון:** שישה Base Stats עם ערכים ופסים בסולם 0–255; אדום מתחת ל-50, צהוב מ-50 עד 89 וירוק מ-90. Abilities מסומנות כ-Regular או Hidden; גובה מוצג במטרים ומשקל בקילוגרמים.
- **Evolution Chain:** מופיעה מיד אחרי ה-Hero, עם תמונות, הדגשת הפוקימון הנוכחי וקישורים. שרשראות ליניאריות מוצגות עם חצים; בהסתעפות מוצג הורה משותף ללא חצים מטעים בין האחים. שרשרת המכילה פוקימון יחיד מוסתרת; בחירת שלב אחרון עדיין מציגה את השרשרת המלאה.
- **Normal / Shiny / Mega:** החלפת תמונה ללא רענון; Mega מוצעת רק לצורות שאומתו באמצעות `is_mega`. בחירת Mega מעדכנת תמונה, סוגים, מדדים, יכולות ומידות, ואפשר לחזור לצורה הרגילה. Shiny זמין בהתאם לתמונות ה-API, עם טיפול בתמונה חסרה או תקולה.
- **Favorites:** עמוד My Pokémon Collection עם מונה, כרטיסים משותפים לקטלוג, הסרה מיידית ומצב ריק עם Discover Pokémon. מזהי המינים המקוריים נשמרים ללא כפילויות ב-localStorage, כך ש-Regular, Shiny ו-Mega חולקים מועדף אחד. נתונים פגומים וכשלי אחסון מטופלים ללא קריסה.
- **Comparison:** בחירה עצמאית בכל צד באמצעות חיפוש או My Favorites, החלפה ללא איפוס הצד האחר, בחירת Regular או Mega מאומתת בכל צד ומניעת אותה צורה בדיוק בשני הצדדים. ניתן להשוות צורות שונות של אותו מין, ו-Swap מעביר גם את הצורה שנבחרה. לתמונה אפקט עומק עדין בעכבר, המושבת במגע ובהעדפת תנועה מופחתת. מוצגים הפרשים, יתרון או תיקו בכל מדד, Total Base Stats וסיכום מספר היתרונות והתיקו. זו השוואת Base Stats בלבד, ולא תחזית לקרב.
- **Pokémon of the Day:** בחירה אקראית מתוך אינדקס המינים המלא, ללא תלות במסננים. הבחירה נשמרת ליום המקומי, מתעדכנת בחצות ובחזרה ללשונית, ונמנעת חזרה על הבחירה הקודמת כשיש חלופה.
- **UX/UI:** מסגרת Pokédex יחידה בכל אחד מארבעת המסכים, רקע כחול מחזורי, כרטיסים ופאנלים טכנולוגיים וקונסולות חיפוש ומדידה. פתיחת Pokédex במסך מלא חושפת את התוכן האמיתי, עם Skip Intro ותמיכה ב-prefers-reduced-motion; היא אינה מופעלת מחדש בניווט. אין מנגנון Screen Transitions בין עמודים. שדרוגי המסכים מומשו; סקירת האיכות הכוללת עדיין פתוחה. כותרות נבחרות משתמשות ב-Lilita One מקומי; [הרישיון](public/fonts/lilita-one/OFL.txt) ו[הקרדיט](public/fonts/lilita-one/CREDITS.md) מצורפים.

מצבי Loading, Error ו-Empty מוצגים בהתאם למסך. עמוד הפרטים כולל Skeleton התואם לפריסתו ושמירת מקום לתמונה, לבקר הצורות ולהתפתחויות בזמן טעינתם; כשל טעינת פרטים מאפשר Retry. אזורים אופציונליים שאינם רלוונטיים מוסרים לאחר הטעינה, ולכן ייתכנו התאמות גובה קטנות. בקשות שהוחלפו או שהתייתרו מבוטלות באמצעות AbortController. טיפול בשגיאות אינו מבטיח פעולה ללא חיבור לרשת.

## התקנה והרצה

נדרשים npm ו-Node.js בטווח `^22.22.2 || ^24.15.0 || >=26.0.0`, בהתאם לשילוב דרישות החבילות המותקנות: Vite, React Router, Vitest ו-jsdom. גרסת Node שמתאימה ל-Vite בלבד אינה בהכרח מספיקה לכל סביבת הפרויקט.

```bash
git clone https://github.com/Yaneerl/Pokedex_Explorer.git
cd Pokedex_Explorer
npm ci
npm run dev
```

פתחו את הכתובת שמציג Vite בטרמינל. אין צורך במפתח API או בהגדרת משתני סביבה עבור המימוש הנוכחי.

## מקורות נתונים וניהול state

- **REST:** בסיס הכתובות הוא `https://pokeapi.co/api/v2/`. נעשה שימוש ב-`pokemon-species` לאינדקס המינים ולפרטי המין, ב-`pokemon` לנתוני הפוקימון, ב-`type` וב-`generation` למסננים, ב-`evolution-chain` להתפתחויות וב-`pokemon-form` לאימות Mega.
- **סיווג:** `https://beta.pokeapi.co/graphql/v1beta` משמש לשליפת מזהי Legendary ו-Mythical. הסיווג נטען כשבוחרים מסנן סיווג.
- **תמונות:** הכתובות מגיעות מתשובות PokéAPI, עם העדפה ל-official artwork וחלופת sprite כאשר זמינה. התצוגה מטפלת גם בכשל טעינת תמונה.
- **קטלוג:** `App.tsx` שומר ב-state את אינדקס המינים ואת החיפוש, המסננים, המיון והעמוד. שמות ומזהים נטענים תחילה; פרטי כרטיסי הקטלוג נטענים לעמוד הנוכחי. חיפוש הקטלוג מושהה ב-300ms.
- **ניווט:** App נשאר מותקן במעבר בין הנתיבים, ולכן מצב הקטלוג נשמר בזיכרון. רענון מלא מאפס את החיפוש והמסננים; בחירות ההשוואה אינן נשמרות לצמיתות.
- **פרטים:** `usePokemonSpecies` משתף את תשובת species בין מידע המין, גילוי Mega ו-Evolution. הנתונים של צורות Mega נטענים בעת הגילוי; הבחירה ביניהן ובהופעת Shiny משתמשת בנתונים שכבר נטענו.
- **השוואה:** reducer מרכז את הבחירות ומניעת הכפילויות; המדדים משמשים מתוך תגובות הפוקימון הקיימות, ללא בקשת סטטיסטיקות נפרדת.
- **שמירה בדפדפן:** `pokedex-explorer:favorites` מכיל מזהי מועדפים; `pokedex-explorer:pokemon-of-the-day:v1` מכיל תאריך מקומי ומזהה יומי. סימון צפייה בפתיחה נשמר ב-sessionStorage תחת `pokedex-explorer:intro-seen:v1`. השמירה מקומית לדפדפן ואינה מסונכרנת לחשבון או למכשירים אחרים.
- **פוקימון היום:** משתמש באינדקס המינים שבקוד (כיום בקשה עם `limit=2000`) ובנתוני כרטיס שכבר נטענו כשאפשר; אחרת נטענים פרטי הבחירה בנפרד. כשל אחסון מוצג ואינו מונע שימוש זמני בזיכרון.

קובץ `src/data/items.json` נשמר מאבן הדרך הראשונה; הוא אינו מקור הנתונים של הקטלוג הנוכחי.

## מבנה הפרויקט

```text

  App.tsx                  נתיבים, state וטעינת קטלוג
  components/              מסכים ורכיבי ממשק; גם בדיקות רכיבים
  hooks/                   species, סיווג, מועדפים, פוקימון היום, פתיחה ועומק אינטראקטיבי
  utils/                   חיפוש, סינון, המרות, שמירה והשוואת מדדים
  types/pokemon.ts         טיפוסי נתונים ותגובות API
  styles/                  Design System וסגנונות לפי אזור
  test/                    הכנת jsdom, נתוני API מטופסים ועזר להפעלת כפתורים בבדיקות
  data/items.json          נתוני אבן הדרך המקומית המקורית
public/                    נכסי SVG ופונט Lilita One מקומי עם רישיון וקרדיט
scripts/log-prompt.mjs      תשתית תיעוד אוטומטי
PRD.md                     אפיון נוכחי ויכולות מתוכננות
tasks.md                   12 משימות מקוצרות, Done when, סטטוסים והפניות ל-Commits
PROMPTS.md                 יומן העבודה הקיים

```

רכיבים מרכזיים: `PokedexFrame`, `CatalogHeader`, `PokemonOfTheDay`, `PokemonFilters`, `CatalogPokemonCard`, `PokemonTypeBadge` ו-`PokemonPagination` בקטלוג; `PokemonDetails`, `PokemonDetailsSkeleton`, `PokemonForms`, `PokemonHero`, `PokemonStats`, `PokemonMeasurements`, `PokemonAbilities` ו-`PokemonEvolution` בפרטים; `PokemonFavorites` ו-`PokemonComparison` בעמודים הנוספים.

## תיעוד ותהליך עבודה

הפרויקט מבוסס על תבנית הקורס. לפי README המקורי של התבנית, PROMPTS.md הוא חלק מההגשה ומציון תהליך העבודה (6 מתוך 20 נקודות); מחוון מעודכן מלא אינו כלול במאגר, ולכן אין במסמך זה אישור לעמידה בכל דרישות המרצה. נשמרו 12 המשימות הראשיות; לפי הסדר שאושר עובדים על משימה 11 לפני החזרה למשימה 10. משימה 10 מוקדשת ל-Mobile Responsiveness & Accessibility: דווחה בדיקת טלפון אמיתי מוצלחת, אך טרם אומתה סקירה מלאה של הגרסה הנוכחית בכל העמודים ברוחבי 375px, 768px ו-1440px. עיצוב ארבעת המסכים מומש, וסגירת סקירת UX/UI נותרה פתוחה במשימה 11. במשימה 12 בדיקות הקוד כבר עברו; הכנה להגנה אישית של 7 דקות ואימות Repository ציבורי מוכן להגשה עדיין פתוחים. Pack Opening Simulator בוטל ואינו בהיקף הפרויקט, ואין דרישת סרטון הדגמה לפי העדכון שנמסר.

ב-Codex, `.codex/hooks.json` מפעיל את `scripts/log-prompt.mjs` באירועי UserPromptSubmit, Stop, Interrupt ו-SessionEnd. הסקריפט מוסיף הודעות משתמש ותשובות גלויות ליומן, עם מניעת כפילויות ושעה באזור Asia/Jerusalem; הסרת רווחים בסופי שורות מונעת trailing whitespace. הוא אינו מתעד תוכן פנימי של הסוכן.

בתבנית קיימות גם הגדרות עבור Claude Code, Gemini CLI ו-Antigravity. היקף הרישום בכל כלי תלוי ב-adapter ובנתונים שהכלי מעביר; האימות הנוכחי מתייחס ל-Codex בלבד. בכלים אחרים יש לפעול לפי AGENTS.md ולבדוק שהרשומה אכן נוספה.

לבדיקת הרשומות האחרונות ב-PowerShell:

```powershell
Get-Content -Encoding UTF8 -Tail 30 PROMPTS.md
```

- שומרים את PROMPTS.md ואת עדכון המשימות יחד עם העבודה ב-Commit שהסטודנט מבצע לאחר בדיקתו.
- לפי הנחיות התבנית, הסטודנט מוסיף הערות אישיות אמיתיות על מה שבדק ושינה בעצמו; אין להשלים בדיקות שלא בוצעו או לייחס בדיקות סוכן לסטודנט.
- אין לשכתב, למחוק או לסדר מחדש רשומות היסטוריות כדי לייפות את היומן. שחזור אפשרי רק ממקור אותנטי, עם סימון מפורש של המקור ומועד השחזור.
- אין להזין ליומן סיסמאות או מפתחות; היומן הוא חלק מהמאגר.

**מגבלות היסטוריות שאומתו בסנכרון 2026-11-02:** תחילת העבודה עם ChatGPT מתועדת בסיכומים ידניים שמסומנים כך; פרומפטים מקוריים מלאים למשימות 1–4 לא אותרו במקורות הזמינים. לא נמצאו הודעות חסרות ב-249 הודעות היסטוריות שנבדקו מול שלושת תמלילי Codex המקומיים של הפרויקט, עד לבקשת סנכרון זו. נמצאה חריגת סדר קיימת ב-2026-10-14: רשומת 20:10 נוספה אחרי 20:12; היא נשמרה במקומה, ללא הסקת הסיבה וללא שינוי הטקסט. הרישום הוא בסדר הוספה ויכול לכלול רשומה מאוחרת בעלת שעה מוקדמת יותר. לא שוחזרו או הומצאו רשומות, ובדיקת המקורות הזמינים אינה הוכחה לשלמות כל שיחות העבר.

כמה שלבי UX/UI אוחדו ב-Commit `6b904e4`, בניגוד לחלוקה המתוכננת ל-Commit לכל שלב; ההיסטוריה נשמרת כפי שנוצרה. מיפוי ה-Commits האמיתיים מופיע ב-tasks.md.
